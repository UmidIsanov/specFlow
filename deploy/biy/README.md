# Подселение «Позиции» на spec.biy.kz

Временное решение: показать клиенту обе программы на одном адресе, пока не
куплен свой сервер. Старую программу не переписываем — она переезжает с порта
8137 на 8138 и продолжает работать как раньше.

## Что увидит клиент

| Адрес | Что открывается |
|---|---|
| `spec.biy.kz/` | страница выбора: две карточки |
| `spec.biy.kz/konverter` | старый конвертер PDF → Excel |
| `spec.biy.kz/pozitsiya` | «Позиция» |

## Как устроено внутри

Снаружи всё так же приходит на порт 8137 — Cloudflare Tunnel и nginx трогать не
нужно. Только теперь на 8137 стоит не конвертер, а маленький шлюз, который
смотрит на адрес и передаёт запрос нужной программе:

```
Cloudflare Tunnel → 8137 шлюз ┬─ /            страница выбора
                              ├─ /pozitsiya   → 3000  интерфейс «Позиции»
                              ├─ /pozitsiya-api → 4000  её API
                              └─ всё прочее   → 8138  старый конвертер
                                                8139  конвертер «Позиции»
```

Шлюз — один файл `deploy/gateway-linux-amd64` (6 МБ, без зависимостей).

## Кто может войти

Вход закрыт паролем: пользователей заводят по приглашению, а не свободной
регистрацией. Первого создаёт установка, если передать `ADMIN_EMAIL` — пароль
она покажет один раз, его стоит сразу сменить на странице «Вход и пароль».
Позже первого пользователя можно завести вручную:

```bash
ADMIN_EMAIL=вы@почта.com npm run access:init --prefix server
```

Остальных зовёт владелец объекта: на странице объекта блок «Команда объекта»
выдаёт ссылку-приглашение на неделю — её пересылают человеку сами, писем
программа пока не шлёт.

Забыли пароль — сбрасываем руками, по той же причине:

```bash
USER_EMAIL=кто@почта.com npm run access:password --prefix server
```

Скрипт покажет новый пароль и выбьет все входы этого человека. Передать пароль
и попросить сменить его на странице «Вход и пароль».

Cookie входа помечается `Secure` только при `COOKIE_SECURE=1` в
`deploy/biy/pm2.config.cjs`. Сейчас пусто: домен отвечает и по http, а с
`Secure` вход по http молча не работал бы. Включить, когда на spec.biy.kz
появится редирект http → https.

## Установка

```bash
cd ~
git clone https://github.com/UmidIsanov/specFlow.git pozitsiya
cd pozitsiya
bash deploy/biy/check.sh        # посмотреть, что умеет сервер
cp ~/converter/.env converter/.env   # ключ Gemini — тот же, что у старой программы
ADMIN_EMAIL=вы@почта.com bash deploy/biy/install.sh   # зависимости, сборка и первый пользователь
bash deploy/biy/pm2-start.sh    # запуск
bash deploy/biy/status.sh       # проверка: везде должно быть 200
```

## Процессами управляет PM2

На этом сервере программы живут под PM2 — там же, где `botlog` и `diamond`.
`pm2-start.sh` переставляет старый конвертер на 8138 (`pm2 restart … --update-env`
с `PORT=8138`), добавляет четыре сервиса «Позиции» из `pm2.config.cjs` и делает
`pm2 save`. Чужие программы в PM2 он не трогает.

Полезное:

```
pm2 list                  что сейчас работает
pm2 logs poz-api          логи одной части
pm2 restart poz-web       перезапустить одну часть
```

Если после перезагрузки сервера ничего не поднялось — значит у PM2 не настроено
воскрешение. Лечится одной командой с правами администратора:
`pm2 startup` и дальше то, что она подскажет.

## Обновление

```bash
cd ~/pozitsiya && git pull && bash deploy/biy/install.sh && bash deploy/biy/pm2-reload.sh
```

`pm2-reload.sh` — именно для обновления: он только перезапускает четыре сервиса
«Позиции» на новом коде. `pm2-start.sh` нужен один раз, при установке: он
переставляет порты и требует свободный 8137, который после установки занят
шлюзом «Позиции», — запущенный повторно, он это заметит и остановится сам.

Первого пользователя заводить второй раз не нужно: `install.sh` создаёт его
только если передать `ADMIN_EMAIL`, а для уже существующей почты пароль не
меняет.

## Как всё вернуть как было

```bash
bash ~/pozitsiya/deploy/biy/pm2-stop.sh
```

Старый конвертер снова встанет на 8137, и `spec.biy.kz` будет открывать его
напрямую, как до подселения.

## Если интерфейс не собирается на сервере

`next build` просит около 1.5 ГБ памяти. Если процесс убивают, соберите на своём
компьютере и перенесите результат:

```bash
# на своём компьютере
cd ~/Documents/specflow/web
BASE_PATH=/pozitsiya NEXT_PUBLIC_API_URL=/pozitsiya-api npm run build

tar czf ~/Desktop/web-build.tgz -C .next standalone
# затем положить архив на сервер и распаковать:
#   tar xzf web-build.tgz -C ~/pozitsiya/web/.next
```

## Чего здесь нет

Входа по паролю. Любой, кто знает адрес, видит все КП и цены. Для показа
клиенту это терпимо, для работы — нет. На своём сервере первым делом сделаем
учётные записи.
