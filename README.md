# SpecFlow — MVP

Продолжение `pdf-spec-converter`. Тот решает шаг 1 (PDF → Excel).
SpecFlow берёт спецификацию дальше по циклу объекта:

```
Спецификация → анализ КП → поставки → склад → акты и списание → ИТД
```

## Что уже работает

**1. Спецификация**
Импорт книги Excel из `pdf-spec-converter`. Проверено на реальной выгрузке АГМК
(МОФ-3 «Ёшлик I», два здания, 111 строк):

- лист выбирается сам — в книге их четыре, и нужен не первый («Итого по наименованиям»),
  а «Сводная спецификация»; при желании лист меняется вручную;
- распознаются все колонки проектной формы: «Поз.», «Наименование и техническая характеристика»,
  «Тип, марка, обозначение», «Код продукции», «Поставщик / Завод изготовитель», «Ед. изм.»,
  «Кол-во», «Примечание», а также «Объект», «Шифр документа», «Система», «Раздел»;
- сохраняются здание, шифр документа проектного института, раздел
  (Оборудование / Кабели и провода / Изделия и материалы) и примечания вида «в т.ч. 15 резерв»;
- строки-разделители разделов, нумерация колонок по ГОСТ и итоговые строки отсеиваются.

**2. Технический анализ КП** — главная боль
Загружается Excel от поставщика, каждая строка автоматически сопоставляется с проектом:

- **Соответствует** — совпал код продукции или артикул;
- **Аналог — годен** — другой артикул того же производителя, характеристики те же;
- **Аналог — проверить** — есть расхождение (характеристика, единица измерения, другой производитель);
- **Нет в проекте** — позиция, которой в спецификации не было.

Порядок признаков: сначала **код продукции** (RBZ-319538, FHF22531382) — он уникален
и не зависит от того, как поставщик написал название; затем артикул, затем название и характеристики.

Матчер учитывает то, на чём ломается ручное сравнение:

- кириллические буквы вместо латинских в артикулах (`С` вместо `C`);
- разные написания одного артикула: `КУИН нг ( А )-FRLS ВЭК 1х2х2.5` = `КУИН нг(А)-FRLS ВЭК 1х2х2.5`;
- правовая форма фирмы: `ООО "КБ Пожарной Автоматики"` = `КБ Пожарной Автоматики`;
- общий корень слов (`аккумулятор` ~ `аккумуляторная`);
- числовые характеристики: `12В 7Ач` и `12В 7,2Ач` — эквивалент (±5%),
  а `24 В /2,5 А` против `24 В /1,5 А` — расхождение по току.

Другой артикул от другого производителя никогда не проходит как «годен» автоматически:
именно так экранированный `КПСЭнг(А)-FRLS` незаметно подменяется на `КПСнг(А)-FRLS` без экрана.

По каждой позиции выводится **причина** заключения — инженер не проверяет всё заново,
а читает готовый разбор и одним кликом ставит своё решение с комментарием.

Сводная матрица «спецификация × все КП» сводит строки в **закупочные позиции**: одна и та же
железка в разных зданиях — это один заказ. На реальном файле 111 строк спецификации
сводятся в 59 позиций, и итоги сходятся с листом «Итого по наименованиям» из выгрузки
один в один — при этом позиции, которые в исходной сводке задвоились из-за лишних пробелов
после распознавания PDF («Дюбель-гвоздь» и «Дюбель -гвоздь»), сводятся правильно.
Матрица показывает: кто что не предложил, где недопоставка по количеству и какое КП
выгоднее по каждой позиции среди технически подходящих.

**2а. Сверка коммерческого предложения с заявкой по теговым номерам**
Проверено на реальной паре документов АГМК МОФ-3: заявка `AGMK-MOF-3-BULK-PR-MR-6450 Rev 2`
(48 страниц, 1027 позиций) и КП поставщика на 71 строку.

Заявка и КП устроены по-разному: в заявке одна строка — один прибор с теговым номером,
в КП строка укрупнённая и перечисляет тэги списком или диапазоном
(`401200-BIAS(F)-9001 ... 401200-BIAS(F)-9009`, кол-во 9). Сравнивать наименования бесполезно —
сверка идёт по **тэгам** и **номерам опросных листов**.

Платформа разворачивает диапазоны в перечни и показывает:

- какие тэги КП есть в заявке, а какие предложены сверх неё;
- какие позиции заявки поставщик не закрыл;
- где количество в строке не сходится с числом перечисленных тэгов;
- где опросный лист в КП не совпадает с указанным в заявке;
- где один тэг предложен в двух строках сразу (двойная поставка).

Заключение выгружается в Excel тремя листами: строки КП, не предложено по заявке, дубли тэгов.

**Сверка по составу систем.** Второй тип КП — на системы целиком (ПЛК, шкафы): проверено на
КП SUPCON G5Pro (223 строки, 8 систем, USD). Строки там не привязаны к тэгам, и платформа
переключается на сверку по составу: сколько шкафов ПЛК и панелей HMI просит заявка против
сколько систем и HMI в КП, каналы DI/DO/AI по каждой системе (из артикулов модулей),
и полевые приборы заявки по объектам — чтобы инженер оценил достаточность каналов.
Несколько КП на одной заявке переключаются вкладками.

**Импорт заявки прямо из PDF.** PDF с текстовым слоем разбирается без конвертера:
границы колонок берутся из линий сетки таблицы, а строка определяется ячейкой,
а не координатой номера позиции — иначе многострочные наименования съезжают на соседнюю позицию.
Сканы текстового слоя не имеют, их по-прежнему готовит `pdf-spec-converter`.

**3. Поставки и склад**
Приход на объект, остаток на складе, план/факт по каждой позиции:
`план — привезено — смонтировано — на складе — дозаказать`. Выгрузка в Excel.

**4. Акты и ИТД**
Акт установки по участку → подписание → **автоматическое списание ТМЦ со склада**.
Если списывается больше, чем есть на складе — система сразу показывает расхождение.
Печатная форма акта (A4/PDF) и журнал отклонений от проекта для исполнительной документации.

## Стек

- `server/` — Node.js + Express + TypeScript, Prisma + SQLite, `xlsx` для импорта/экспорта
- `web/` — Next.js 15 (App Router) + TypeScript + Tailwind CSS 4

SQLite выбран для MVP: одна папка, никакой инфраструктуры. Переезд на PostgreSQL — смена
`provider` в `prisma/schema.prisma`, код не меняется.

## Запуск

```bash
# 1. API
cd server
npm install
npm run db:reset     # схема + демо-данные объекта АГМК
npm run dev          # http://localhost:4000

# 2. Веб
cd ../web
npm install
npm run dev          # http://localhost:3000
```

Демо-данные: объект АГМК (АБК медеплавильного завода), спецификация на 15 позиций
(ПС, СОУЭ, СКС, СОТ, ПЕРИМЕТР, АПТ), два КП от разных поставщиков с аналогами
и недопоставкой, одна поставка, подписанный и черновой акт, одно отклонение от проекта.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET/POST` | `/api/projects` | объекты |
| `GET/POST` | `/api/projects/:id/spec` | спецификация (JSON) |
| `POST` | `/api/spec/inspect` | листы книги, распознанные колонки, превью |
| `POST` | `/api/projects/:id/spec/import` | импорт спецификации из Excel (параметр `sheet`) |
| `POST` | `/api/projects/:id/spec/import-pdf` | импорт заявки/спецификации из PDF с текстовым слоем |
| `POST` | `/api/projects/:id/offers/json` | загрузка КП строками с перечнями тэгов |
| `GET` | `/api/projects/:id/tag-audit` | сверка КП с заявкой по тэгам и опросным листам |
| `GET` | `/api/projects/:id/export/tag-audit.xlsx` | выгрузка заключения по сверке |
| `POST` | `/api/projects/:id/offers/import` | импорт КП из Excel + анализ |
| `POST` | `/api/offers/:id/analyze` | пересчитать сопоставление |
| `PATCH` | `/api/offer-items/:id` | решение инженера по позиции |
| `GET` | `/api/projects/:id/comparison` | матрица «спецификация × КП» |
| `GET/POST` | `/api/projects/:id/deliveries` | поставки (приход на склад) |
| `GET/POST` | `/api/projects/:id/acts` | акты установки |
| `POST` | `/api/acts/:id/sign` | подписать акт + списать ТМЦ |
| `GET` | `/api/projects/:id/plan-fact` | план/факт по объекту |
| `GET` | `/api/projects/:id/export/spec.xlsx` | спецификация + сводка по наименованиям |
| `GET` | `/api/projects/:id/export/comparison.xlsx` | матрица «спецификация × все КП» |
| `GET` | `/api/offers/:id/export.xlsx` | техзаключение по одному КП + что не предложено |
| `GET` | `/api/projects/:id/export/plan-fact.xlsx` | план-факт + лист «дозаказать» |
| `GET/POST` | `/api/projects/:id/deviations` | отклонения от проекта (ИТД) |

## Что дальше (вне MVP)

- Импорт спецификации напрямую из PDF — подключить `pdf-spec-converter` как шаг внутри SpecFlow.
- План/факт и акты в разрезе зданий объекта (данные уже хранятся, нужен разрез в интерфейсе).
- Роли: инженер, снабжение, кладовщик, руководитель проекта.
- Полный комплект ИТД по нормам РУз (не только акт установки).
- Фото-фиксация монтажа с привязкой к акту.
- Несколько объектов одного подрядчика в одной сводке.
